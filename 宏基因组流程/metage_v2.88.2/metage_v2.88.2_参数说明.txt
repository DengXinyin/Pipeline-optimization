metage_v2.88.2 参数说明
========================================

适用工作流
----------
workflow 名称：metage_v2_88_2
WDL 文件：metage_v2.88.2.wdl

说明：本文以当前 WDL 的实际声明和分支条件为准。平台页面中的“暂无”通常表示
WDL 可选参数没有平台默认值；提交 JSON 时可写 null，也可以省略该参数。


一、当前项目参数示例
--------------------

项目：SNCY042726060201_刘嘉陵_v2.88.2

当前配置属于：full 完整运行、不分箱、不去宿主、不启用 Kraken2、
无参考样本组装/SNP 分析。分析固定开启，物种 Beta 固定输出四种距离。

关键参数如下：

  binning         = "no"
  run_mode        = "full"
  host            = "none"
  isbwa           = "yes"
  use_kraken2     = "no"
  kraken2_db      = null
  ref_sample      = null
  parent_workflow_dir = null

无需提交 analyse、do_unifrac、tax_tree 或 func_tree。物种分类树从上游注释和
mapdir/database/taxonomy 自动生成，默认输出 Bray-Curtis、Binary Jaccard、
Weighted UniFrac 和 Unweighted UniFrac。


二、工作流级输入参数
--------------------

1. datapath

  完整名称：metage_v2_88_2.datapath
  类型：String
  当前 WDL 默认值：
    /cephfs_data/genostack_v3/genostack_php/project_data/21499/SNDF042726061801_testdata/testdata
  含义：项目输入数据目录。测试者必须同时提供以下三个文件：
    data.xlsx
    project_info.json
    report_no.txt

  输入 data.xlsx 至少包含 sample 和 comparison 工作表。输入检查 task 会读取外部
  project_info.json 和 report_no.txt，并输出标准化 data.xlsx；标准化文件固定包含：
    sample       fastqfile、sample、group
    comparison   比较组定义
    information  project_info.json 的全部顶层字段以及报告编号

  客户名称、客户单位、项目编号、项目名称不再从 sample 工作表读取。

  full：填写本次完整项目数据目录。
  incremental/reuse：填写项目当前完整数据目录；incremental 的新增或变更样本表
  由 ${project_root}/incremental_data/ 提供。

  当前项目填写：
    /cephfs_data/genostack_v3/genostack_php/project_data/SNCY042726060201_刘嘉陵_v2.88.2

2. rawdatapath

  完整名称：metage_v2_88_2.rawdatapath
  类型：String
  含义：FASTQ 原始数据所在目录。
  full/incremental 模式使用；reuse 模式复用父流程上游结果，一般不会重新读取 FASTQ。

  当前项目填写：
    /public/nfs_data/public_file_data/seqrawData/metage_raw/SNCY042726060201/data

3. project_root

  完整名称：metage_v2_88_2.project_root
  类型：String
  含义：项目根目录，用于管理项目级样本注册表和增量数据。

  固定目录约定：
    ${project_root}/data/sample_registry.tsv
    ${project_root}/incremental_data/

  当前项目填写：
    /cephfs_data/genostack_v3/genostack_php/project_data/SNCY042726060201_刘嘉陵_v2.88.2

4. mapdir

  完整名称：metage_v2_88_2.mapdir
  类型：String
  当前 WDL 默认值：/public/nfs_data/public_file_data/metagenome-DB
  含义：宏基因组公共数据库根目录。节点或容器内必须能够访问该路径。

5. host

  完整名称：metage_v2_88_2.host
  类型：String
  默认值："none"
  含义：宿主序列去除类型。

  常用值：
    none   不去宿主
    human  去人源序列（需数据库和脚本支持）
    mouse  去小鼠序列（需数据库和脚本支持）

  不建议填写未经当前数据库配置支持的任意名称。

6. binning

  完整名称：metage_v2_88_2.binning
  类型：String
  默认值："no"
  合法业务值："yes" 或 "no"
  含义：是否运行 binning、去冗余、定量分类及 bins 统计分支。

  注意：当前 WDL 注释注明 isbwa=no 且 binning=yes 的组合暂不完整支持。

8. isbwa

  完整名称：metage_v2_88_2.isbwa
  类型：String
  默认值："yes"

  兼容性参数。当前版本 WDL 虽然声明了该参数，但没有在任务条件或 task input 中实际
  使用，因此修改它目前不会跳过或启用 bwa_no。平台可暂按既有规则填写：full 填 yes，
  reuse/incremental 通常填 no；不要依赖该参数控制流程分支。

9. run_mode

  完整名称：metage_v2_88_2.run_mode
  类型：String
  默认值："full"
  可用值：full、incremental、reuse

  full：
    首次运行或全部样本完整重跑。
    读取 FASTQ 并执行质控、组装、基因预测、比对和注释。
    parent_workflow_dir 不需要填写。

  incremental：
    仅新增样本运行 QC、组装、基因预测、定量、tax/func 和 8 个扩展数据库注释，
    各数据库分别与父流程累计结果合并，再对完整项目重建 tax_base、func_base、
    diff 和 report。已有样本 FASTQ 发生变化时仍应 full。
    必须填写 parent_workflow_dir。
    必须准备 ${project_root}/incremental_data/。
    datapath 仍应表示项目当前完整数据；incremental_data 保存增量输入。

  reuse：
    不重跑 FASTQ 上游，复用父流程的质控、组装、注释等结果。
    适合样本删除、改名或改分组后重新汇总。
    必须填写 parent_workflow_dir。

  注意：当前 WDL 没有显式枚举校验。不要填写上述三种值以外的字符串，否则可能出现
  分支缺失以及 select_first 取不到文件的问题。

10. parent_workflow_dir

  完整名称：metage_v2_88_2.parent_workflow_dir
  类型：String?（可选）
  默认值：无/null
  含义：此前成功运行的同一项目 Cromwell workflow UUID（只填写 UUID，不填写完整路径）。
  WDL 会自动拼接固定根目录：
    /cephfs_data/genostack_v3/genostack_cromwell/cromwell-executions/metage_v2_88_2/
  最终父流程目录为上述根目录加 UUID。目录名必须是已成功运行的父 workflow ID。

  full：必须为空。
  incremental/reuse：必须填写父 workflow UUID，而且对应目录内应保留 WDL 中
  deal_parameter 所引用的累计结果。首次增量一般填写 full UUID；连续增量必须填写
  最近一次成功且样本累计最完整的 incremental UUID。不要一直指向首次 full，
  也不要填写完整路径或最终 resfile 目录。deal_parameter 会优先读取 merged/*，
  并兼容旧 full、旧任务名和 cacheCopy。

11. use_kraken2

  完整名称：metage_v2_88_2.use_kraken2
  类型：String
  默认值："no"
  合法业务值："yes" 或 "no"
  含义：是否启用 Kraken2 物种注释。

  "yes" 时必须同时填写 kraken2_db。仅填写 "yes" 而 kraken2_db=null 不会运行 Kraken2 task，
  但会改变 clean reads 的保留行为，因此不推荐这种不完整组合。

12. kraken2_db

  完整名称：metage_v2_88_2.kraken2_db
  类型：String?（可选）
  默认值：无/null
  含义：Kraken2 数据库目录。

  Kraken2 注释运行条件：
    use_kraken2="yes" 且 kraken2_db 非空；上游模式为 full 或 incremental。

  Kraken2 差异分析运行条件更严格：
    use_kraken2="yes"、kraken2_db 非空且 run_mode="full"。

13. kraken2_anno.threads

  完整名称：metage_v2_88_2.kraken2_anno.threads
  类型：Int
  默认值：16
  含义：Kraken2 注释线程数。仅在 kraken2_anno task 实际运行时生效。

14. kraken2_tax_diff.threads

  完整名称：metage_v2_88_2.kraken2_tax_diff.threads
  类型：Int
  默认值：8
  含义：Kraken2 物种差异分析线程数。仅在该 task 实际运行时生效。

15. ref_sample

  完整名称：metage_v2_88_2.ref_sample
  类型：String?（可选）
  默认值：无/null
  含义：触发参考样本组装、参考比对和 SNP calling 分支的样本名。

  应填写 data.xlsx/sample-metadata 中能够识别的样本 ID，不是直接填写参考基因组文件路径。
  当前 WDL 会先由该样本执行 ref_assembly，再将生成的 ref_fasta 用于 ref_mapping 和
  snp_calling。仅 full/incremental 上游分支中生效。

16. 物种 Beta（固定行为，不是输入参数）

  tax_diff 和 kraken2_tax_diff 默认输出以下四类距离及 PCoA、NMDS 可视化：
    Bray-Curtis
    binary Jaccard（presence/absence）
    weighted UniFrac
    unweighted UniFrac

  分类树由上游物种注释的 TaxID 和 mapdir/database/taxonomy 自动裁剪生成。
  功能分析没有跨 KEGG/GO/CAZy/eggNOG 的统一上游树，因此不伪造功能 UniFrac；
  功能 Beta 继续使用 Bray-Curtis 和 Binary Jaccard。

五、主要输出参数
----------------

1. respath
  最终结果目录，由 resFile task 生成。

  KEGG 增强表位于各 group 的：
    Result/Result/groupN/7-FunctionAnnotation/1.KEGG/KEGG.tpm.csv
  表中包含单列 taxonomy、KO、KO 注释、KEGG pathway 层级与其他原始 KEGG 字段。

  GeneID 综合注释表位于：
    Result/Result/GeneAnnotationSummary/All_gene_annotation_summary.csv
    Result/Result/GeneAnnotationSummary/All_gene_annotation_summary.xlsx
  CSV 固定生成；Excel 仅在行数不超过 Excel 上限且写入成功时生成。每个 GeneID
  一行，taxonomy 为以下划线连接的界门纲目科属种单列，其余数据库原始注释字段
  分别成列。

2. pdfFile
  最终 PDF 报告路径。

3. docxpath
  最终 Word/docx 报告路径。

4. jsonpath
  res2json 生成的前端结果索引 JSON。

5. reportNo
  报告编号相关输出目录或文件。

6. infoFile
  本次流程使用的 project_info 文件。

7. kraken2_out
  Kraken2 原始注释输出。未启用 Kraken2 时为空。

8. kraken2_tax_base_result
  Kraken2 基础物种统计结果。未启用时为空。

9. kraken2_tax_diff_result
  Kraken2 差异分析结果。仅满足对应 full/差异分析条件时存在。

10. ref_assembly_dir
  参考样本组装结果。ref_sample 为空时不存在。

11. ref_mapping_dir
  参考基因组比对结果。ref_sample 为空时不存在。

12. snp_dir
  SNP calling 结果。ref_sample 为空时不存在。

15. choose_plot_style.plot_style
  流程内部生成的统一绘图配置文件。字体、主题、尺寸等由 WDL 固定配置，通常无需用户填写。

16. prepare_registry_context.registry_tsv / registry_md5 / incremental_datapath
  reuse/incremental 模式的内部注册表输出。full 模式通常为空，不需要人工配置。

17. check_input_with_raw.*、kneaddata_no.*、megahit_no.* 等 task 输出
  属于工作流内部中间结果和任务间传递参数。平台可能全部展示，但不是提交时需要填写的
  workflow 输入参数。


六、提交前检查清单
------------------

  [ ] datapath、rawdatapath、project_root 和 mapdir 在 node1/容器中可访问。
  [ ] 输入目录同时存在 data.xlsx、project_info.json、report_no.txt。
  [ ] data.xlsx 的 sample 表、comparison 表及 FASTQ 样本名一致。
  [ ] project_info.json 包含客户名称、客户单位、项目编号、项目名称。
  [ ] report_no.txt 只包含一个非空报告编号。
  [ ] run_mode 仅使用 full、incremental、reuse。
  [ ] incremental/reuse 已填写正确的父 Cromwell workflow UUID（只填 task ID）。
  [ ] use_kraken2="yes" 时 kraken2_db 非空且数据库完整。
  [ ] mapdir/database/taxonomy 中 nodes.dmp、names.dmp、merged.dmp 完整可读。
  [ ] ref_sample 非空时填写的是有效样本 ID，而不是 fasta 路径。
